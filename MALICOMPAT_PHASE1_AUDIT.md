## 1. Executive Summary

This audit establishes the concrete hardware, driver, kernel, and software environment of the test device (Samsung Galaxy A20 running Feather Project 6.0), conducts a read-only source audit of the reference game project (*NFSMW Android Evolved* v0.5.4 / `codepdbh/nfsmw-android`), and correlates real device capabilities against renderer requirements to design **MaliCompat** as an independent, reusable graphics compatibility layer.

### Key Audit Findings:
1. **Device Environment Verified via ADB Root (`su -c`):**
   - The device is a **Samsung Galaxy A20** (`universal7884B`, Exynos 7884 SoC) running **Feather Project 6.0** (a One UI 6 / Android 14 ROM with build fingerprint spoofing `SM-S901B`, API 34).
   - The kernel is `4.4.302-p6` (aarch64) with **KernelSU Next** root access enabled.
   - The physical GPU is an **ARM Mali-G71 MP2** (Bifrost 1st generation, architecture `G71`, core ID `0x60a00002`, Vendor ID `0x13B5`).
   - The active Vulkan driver is Samsung's vendor implementation `/vendor/lib64/hw/vulkan.universal7884B.so`, build string **`v1.r26p0-01eac0`**, driver ID `VK_DRIVER_ID_ARM_PROPRIETARY` (9), driver version `109051904`.
   - The driver exposes **Vulkan 1.1.131**. It **does not** expose Vulkan 1.2 or Vulkan 1.3.

2. **Core Graphics Incompatibility Identified:**
   - The device **completely lacks descriptor indexing**: neither Vulkan 1.2 core nor the extension `VK_EXT_descriptor_indexing` is supported by Mali-G71's driver `r26p0`.
   - The following critical feature flags required by the native renderer are missing (`false`):
     - `runtimeDescriptorArray`
     - `descriptorBindingPartiallyBound`
     - `descriptorBindingSampledImageUpdateAfterBind`
     - `descriptorBindingUpdateUnusedWhilePending`
   - Texture format support: Mali-G71 reports **no hardware support for linear filtering on BC formats** (`optimalTilingFeatures` has `SAMPLED_IMAGE_BIT` and `TRANSFER_DST_BIT`, but lacks `SAMPLED_IMAGE_FILTER_LINEAR_BIT`).
   - Max bound descriptor sets limit: `maxBoundDescriptorSets = 4`.

3. **Reference Game Project Status (v0.5.4):**
   - The reference port already includes:
     - 4-descriptor-set SPIR-V remapping (`JuntarConjuntos` in `app/src/nfsmw_spirv_descriptores.h`), packing 3D and cube maps into set 1 and dropping set count from 5 to 4.
     - Automatic occlusion query disabling on Mali (`OclusionGpu` in `app/src/nfsmw_gpu_compatibilidad.h`) for ARM vendor `0x13B5`.
     - CPU decompression fallback for BC1–BC5 textures.
     - External Vulkan driver loading via `libadrenotools` (`rex_android_open_vulkan`).
   - **However**, the native renderer hard-fails at initialization (`app/src/nfsmw_nativo_dibujos.cpp:2225`) because it strictly mandates `runtimeDescriptorArray` and `descriptorBindingPartiallyBound`.
   - The game was launched on the device and its diagnostic report was extracted: the probe correctly marked the GPU as **incompatible (`compatible: false`)** due to the absence of `VK_EXT_descriptor_indexing` and the four dynamic descriptor indexing flags.

4. **Recommendation:**
   - **INVESTIGATE / ARCHITECT (GO for MaliCompat Architecture)**. Emulating or re-architecting descriptor sets away from `UPDATE_AFTER_BIND` bindless arrays is feasible via static binding or dynamic UBO/SSBO indirection in MaliCompat. However, running the unmodified native renderer on stock Mali-G71 drivers is impossible without a translation shim.

## 5. Reference Game Project Audit (`codepdbh/nfsmw-android` v0.5.4)

### 5.1 Existing Mali-Specific Workarounds in Upstream
1. **Four Descriptor Sets Remapping (`app/src/nfsmw_spirv_descriptores.h` & `nfsmw_nativo_dibujos.cpp:8177`):**
   - Xbox 360 Xenos recompiled shaders originally expected 5 descriptor sets: Set 0 (2D textures), Set 1 (3D textures), Set 2 (Cube textures), Set 3 (Samplers), Set 4 (UBOs).
   - Upstream merged victorgbd's fork logic (`JuntarConjuntos`): checks if `maxBoundDescriptorSets == 4`. If true, Set 2 (Cube) is combined into Set 1 at binding 1, Set 3 (Samplers) shifts to Set 2, and Set 4 (UBO) shifts to Set 3. SPIR-V bytecode is rewritten on the fly.
2. **Occlusion Query Suppression (`app/src/nfsmw_gpu_compatibilidad.h:8`):**
   - Function `OclusionGpu(modo, android, vendor)`:
     ```cpp
     inline bool OclusionGpu(std::string_view modo, bool android, uint32_t vendor) {
       if (modo == "off") return false;
       if (modo == "on") return true;
       return !(android && vendor == 0x13B5); // Arm
     }
     ```
   - Avoids driver crashes in Mali's proprietary `kbase`/userland query pool reset.
3. **CPU Texture Decompression for BC Formats (`app/src/nfsmw_nativo_dibujos.cpp:2242`):**
   - Automatically detects whether BC formats support optimal linear sampling. If not (as on Mali-G71), textures are decompressed to RGBA8/R8/RG8 on the CPU during upload.
4. **Memory Barrier Publishing (`docs/compatibilidad-android-0.5.4.md:8`):**
   - ARM64 memory ordering fix using atomic store-release and acquire-load for cross-thread command queue submission.

### 5.2 Remaining Blockers in Upstream for Mali-G71
- **The Bindless Descriptor Model:**
  The native renderer (`C6`) in `nfsmw_nativo_dibujos.cpp:2211` constructs its texture cache around unbounded/partially-bound descriptor arrays with `VK_DESCRIPTOR_BINDING_UPDATE_AFTER_BIND_BIT`. It maintains a ring buffer of descriptor updates and expects the driver to allow recording draws while textures are streamed.
- Because Mali-G71's driver `r26p0` does not support `UPDATE_AFTER_BIND` or `PARTIALLY_BOUND`, the game aborts graphics initialization immediately:
  ```text
  [nativo] C6: el dispositivo Vulkan no tiene runtimeDescriptorArray: no se dibuja
  ```

## 6. Root Cause Classification (Hardware vs Driver vs Engine)

| Layer | Component | Classification & Technical Rationale |
| :--- | :--- | :--- |
| **Driver Implementation** | Lack of `VK_EXT_descriptor_indexing` | **Driver Limitation (High Confidence)**: The hardware Mali-G71 has general register banking and dynamic sampler addressing (`shaderSampledImageArrayDynamicIndexing: true`), but the ARM `r26p0` driver (circa Android 9/10 era) was frozen before Vulkan 1.2 features and descriptor indexing were backported to Bifrost 1st Gen. |
| **Driver Implementation** | Lack of BC Linear Filtering | **Driver/Hardware Feature Gap (High Confidence)**: Mali GPUs focus on ASTC and ETC2; BC texture formats only have minimal transfer/sample support without hardware filtering units for BC blocks. |
| **Engine / Renderer** | Unconditional Descriptor Indexing Requirement | **Renderer Architectural Assumption (Very High Confidence)**: The game's native renderer is architected around D3D12/Vulkan bindless descriptor heaps. It lacks a fallback path for traditional, statically-bound descriptor sets (e.g., binding textures directly per material or batching via dynamic offsets). |
| **Custom ROM / Kernel** | Feather Project 6.0 / Kernel 4.4.302 | **Neutral / Transparent (High Confidence)**: The custom ROM cleanly exposes `/dev/mali0` and Android Vulkan loader endpoints. The limitation originates directly from the vendor binary blob (`/vendor/lib64/hw/vulkan.universal7884B.so`). |

## 7. Proposed Independent MaliCompat Architecture

To solve these graphics incompatibilities without patching every individual game engine or recompiled port, **MaliCompat** will be designed as an independent, modular Vulkan layer / compatibility runtime.

```mermaid
flowchart TD
    App[Game / Native Recompiled Engine] -->|Vulkan Calls| Shim[MaliCompat Vulkan Compatibility Layer]
    subgraph MaliCompat [MaliCompat Runtime Framework]
        Shim --> Probe[Capability & Conformance Engine]
        Shim --> Trans[Descriptor Set Emulation Layer]
        Shim --> SPIRV[SPIR-V Transform & Emulation Engine]
        Shim --> Tex[BC/ASTC Texture Decompressor Pool]
        Shim --> Sync[ARM Barrier & Queue Sanitizer]
    end
    Trans -->|Traditional Bound Sets / UBO Atlas| Driver[Mali Vendor Vulkan Driver (vulkan.universal7884B.so)]
    Driver --> Hardware[Mali-G71 GPU]
```

### Module Breakdown:

1. **`MaliCompat-Probe` (Diagnostic & Capability Inspector):**
   - Independent standalone executable (`malicompat-probe`) running on Android ARM64.
   - Probes `vkGetPhysicalDeviceProperties2`, `vkGetPhysicalDeviceFeatures2`, format capabilities, memory heap properties, and driver quirks without requiring game assets.
   - Emits structured JSON compatible with CI/CD and automated testbeds.

2. **`MaliCompat-DescriptorShim` (Descriptor Indexing Emulation):**
   - Intercepts `vkCreateDescriptorSetLayout`, `vkAllocateDescriptorSets`, `vkUpdateDescriptorSets`, and `vkCmdBindDescriptorSets`.
   - For drivers lacking `VK_EXT_descriptor_indexing`:
     - **Strategy A (Static Slots):** Re-maps sparse descriptor tables to compact descriptor arrays bounded by `maxPerStageDescriptorSampledImages` (128 on Mali-G71).
     - **Strategy B (Atlas & Dynamic Offsets):** Converts dynamic indexing to push descriptors or indexed UBO/SSBO lookups where supported.
     - **Strategy C (Descriptor Set Virtualization):** Tracks CPU-side shadow descriptor tables and flushes them before `vkCmdDraw` rather than relying on `UPDATE_AFTER_BIND`.

3. **`MaliCompat-SPIRV` (Bytecode Transformer):**
   - Intercepts `vkCreateShaderModule`.
   - Translates SPIR-V 1.4/1.5 down to SPIR-V 1.3 / Vulkan 1.1.
   - Strips `RuntimeDescriptorArray` capabilities and rewrites `OpVariable` descriptor arrays into fixed-size bindings.
   - Re-decorates DescriptorSet indices when hardware limits `maxBoundDescriptorSets` to 4.

4. **`MaliCompat-FormatShim` (Texture Compression Fallback):**
   - Provides fast ARM NEON-accelerated CPU decompression for BC1, BC2, BC3, BC4, BC5 formats into RGBA8/R8 when the driver lacks linear filtering or sampling.

5. **`MaliCompat-Conformance` (Micro-Test Suite):**
   - Minimal standalone Vulkan test binaries testing:
     - 4-set binding limits.
     - Partial update hazard tests.
     - Occlusion query pool stability on `/dev/mali0`.

## 8. Minimum Viable Proof-of-Concept (PoC) Plan

### Step 1: Standalone Micro-Probe (`malicompat_probe`)
- Build a lightweight standalone C++20 ELF (`malicompat_probe`) compiled with Android NDK targeting `arm64-v8a`.
- Deploy to `/data/local/tmp/` via ADB.
- Validate that it can query device capabilities, test logical device creation, and reproduce Mali-G71's driver response in isolation.

### Step 2: Descriptor Virtualization Micro-Test
- Create a minimal Vulkan render test that attempts to draw textured quads using:
  1. Bindless descriptor indexing (to verify expected driver rejection).
  2. A shimmed traditional descriptor set with pre-submission updates (to verify visual rendering on Mali-G71).

### Step 3: Layer / Shim Library Integration
- Compile `libmalicompat.so` as a Vulkan layer or preload wrapper intercepting `libvulkan.so` calls.

## 9. Risks and Unresolved Questions

1. **Performance Cost of Descriptor Virtualization:**
   - On Mali's Tile-Based Deferred Rendering (TBDR) architecture, frequently re-binding descriptor sets or performing CPU-side shadow flushes before every draw call introduces CPU overhead. Measuring draw call throughput will be essential.
2. **SPIR-V Re-indexing Complexity:**
   - Shaders that use dynamic indices computed at runtime (`texture(sampler2D(textures[nonuniformEXT(id)], samplers[s]))`) cannot easily be resolved statically if `id` varies per pixel. In those cases, branching or texture atlas translation is required.
3. **Mesa/PanVK Long-Term Feasibility:**
   - Upstream Mesa PanVK is focused on newer Mali GPUs (Valhall, v9/v10) and Bifrost v7+. Mali-G71 is Bifrost v6 (`G71`), which relies on older `panfrost` kernel interfaces not present in Samsung's 4.4 Exynos kernel. A userland Vulkan shim on the vendor driver is by far the highest-probability path.

## 10. Audit Conclusion and Recommendation

### Recommendation: **INVESTIGATE / ARCHITECT (GO)**

- **Rationale:** The environment and failure mechanism are now 100% understood. The device is fully accessible with root access, the driver limitations are quantitatively proven via `cmd gpu vkjson` and the official game diagnostic probe, and the root cause is confirmed to be the **absence of descriptor indexing (`runtimeDescriptorArray`, `partiallyBound`, `updateAfterBind`) in the Mali `r26p0` Vulkan 1.1 driver**.
- **Immediate Next Action:** Create the initial standalone repository skeleton for **MaliCompat** with a minimal standalone testbed (`malicompat-probe`) to benchmark and test descriptor set virtualization on the Samsung Galaxy A20 without altering any game files or device system libraries.
